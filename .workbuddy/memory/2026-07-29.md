## SettingsPanel 运行时崩溃修复（Cannot read properties of undefined reading 'json_formatter'）

报错栈指向 `SettingsPanel.tsx:676`，但磁盘当前文件仅 589 行 → dev 服务器（localhost:1420）运行的是**重写前的旧版本**，HMR 未同步；用户需重启 dev 服务器才能生效。根因与修复如下：

### 根因
- `SettingsPanel` 在 `useEffect` 里读取 `config.toolPrefs['json_formatter']?.values?.indent`。`?.` 只保护了 `.values`/`.indent`，未保护 `config.toolPrefs` 本身。
- 当持久化配置（Rust `config_get_all` 返回）缺少 `toolPrefs` 字段（旧版本配置遗留）时，`config.toolPrefs` 为 `undefined`，访问 `['json_formatter']` 抛 `Cannot read properties of undefined (reading 'json_formatter')`。

### 修复
1. **治本** `src/store/configStore.ts`：新增 `normalizeConfig(raw)`，在 `loadConfig` 成功时用 `DEFAULT_USER_CONFIG` 深合并回填缺失字段（general/theme/shortcuts/toolPrefs/favorites），确保 `toolPrefs` 永不为 `undefined`。
2. **兜底** `src/components/SettingsPanel.tsx`：`config.toolPrefs?.['json_formatter']?.values?.indent`（对 `toolPrefs` 加 `?.`）。
3. **configStore 乐观更新兜底**：`setConfig`/`applyConfigChanged` 中 `{ ...current.toolPrefs }` → `{ ...(current.toolPrefs ?? {}) }`，`favorites` 同理。
4. **回归测试** `src/components/SettingsPanel.test.tsx`：新增用例，构造缺 `toolPrefs` 的旧配置，验证渲染不崩溃且 JSON 缩进回退为 2。

### 验证
- `tsc --noEmit` 0 错误；`pnpm test` 141/141 通过（含新增用例）。
- 用户侧：**必须重启 dev 服务器**（`pnpm dev` / `pnpm tauri dev`）方能加载修复后的当前代码。

### Bugfix(15:06): Monaco "Illegal value for token color: oklch(...)"
- 现象：编辑器随调色板定义主题时报错崩溃，根因是 `editor.foreground` 等字段接收了 `--card-foreground` 的 `oklch()` 值，Monaco 仅接受 hex。
- 修复：`code-editor.tsx` 将 `cssVar()` 改为 `resolveColor()`，借助临时元素 + `getComputedStyle().color` 把任意色彩函数规范化为 `#rrggbb(aa)` hex，再传给 Monaco 主题；保留跟随调色板能力。`tsc` 0 错误。
- 经验：凡是要把 CSS 变量喂给 Monaco / SVG / Canvas 等只认 hex 的渲染层，都必须先做 hex 规范化，不能直接传 oklch/oklab/rgb 字符串。
