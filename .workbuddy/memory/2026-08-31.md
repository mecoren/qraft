## 窗口控制按钮图标统一

- 文件：`src/components/ui/window-controls.tsx`
- 初版：将四个图标统一为 `size-3`，并把「还原」由 `Copy` 改为 `SquareStack`。
- 修订（根据截图反馈）：`SquareStack` 实际渲染呈“链环”状，`Square` 在 12px 下仍显小。改为内联 SVG 自绘：
  - 最小化：居中横线（初版画在底部导致与居中图标不对齐，已修正）；
  - 最大化：居中 10×10 方框；
  - 还原：左下+右上两个重叠方框；
  - 关闭：居中 X。
  - 统一尺寸 `size-3.5`（14px）、统一描边 1.25、圆角 rx=0.5，进一步贴近参考图的细线方框风格。
- 终版（对齐 Win11 原生规格 + 参考图重叠方块风格）：
  - 渲染尺寸提升到 `size-4`（16px），内容统一落在 10×10 居中盒子 = Win11 原生 caption 图标比例；
  - 「还原」图标重画：前层完整方块 (3,6,7,7,rx=1) + 后层仅绘制可见 L 形描边 `M6 6 L6 3 L13 3 L13 10 L10 10`，
    后层被前层遮挡部分不再绘制——此前两个完整 rect 重叠会在交叉区形成"链环"观感，是用户反复反馈"别扭"的根因；
  - 最大化：10×10 方框；最小化：居中横线；关闭：居中 X；描边统一 1.25。
- 圆角修正（用户反馈"内外都要圆"）：SVG 描边以路径为中心线，可见外侧圆角 = rx + strokeWidth/2，
  内侧 = rx - strokeWidth/2。rx=1 时内侧仅 0.375px 接近直角。改用 `CORNER_RADIUS = 1.625`：
  内侧圆角恰为 1px、外侧 2.25px，与 Win11 窗口圆角曲率观感一致；最大化方框与还原图标前层方块共用该值。
- 后层 L 形描边圆角化（用户反馈"外圈也要改"）：后层路径三个可见拐角由直角折线改为
  与 CORNER_RADIUS 同半径的圆弧过渡（`A` 命令模板拼接，单一来源），
  否则 round join 仅提供 0.625px 外圆角，与前层 2.25px 不一致。
- 验证：`tsc --noEmit` 通过；`Titlebar.test.tsx` / `PopoutApp.test.tsx` 单独通过。

## 标题栏功能名与项目名位置对调（VS Code 式布局）

- 文件：`src/components/layout/Titlebar.tsx`、`src/styles/globals.css`、`src/components/layout/Titlebar.test.tsx`
- 需求演变：
  1. 初版诉求「功能名与项目名调换位置」：原左段「文本编辑器 文件 视图」、中段「Qraft」。
  2. 用户澄清最终预期：**左段 = `Qraft` + 工具菜单栏（文件/视图），中段 = 功能名（文本编辑器）居中**。
     即菜单栏归属品牌区（左），仅功能名居中 —— 对齐 VS Code「左菜单 + 中标题」观感。
- 最终实现：
  - 左段 `.titlebar-left`：`Logo + Qraft` + `ToolMenuBar`（有菜单时紧随品牌右侧）；
  - 中段 `.titlebar-center`（absolute 居中）：当前工具图标 + 名称 + pop-out 按钮；
  - 移除中段的 `data-tauri-drag-region`，避免工具按钮被误拖拽；
  - `.titlebar-center` 加 `pointer-events: none`，直接子元素恢复 `pointer-events: auto`，空白区点击穿透到下方拖拽填充区；
  - 新增 `.titlebar-left .menubar-root { margin-left: var(--space-2) }`，品牌与菜单之间留出 12px（gap 4px + margin 8px）语义间隔。
- 测试调整：`Titlebar.test.tsx` 用例改为断言「品牌 → 菜单栏 → 工具名」的 DOM 顺序（菜单栏先于工具名）。
- 验证：`pnpm test` 996 用例全绿；`pnpm exec tsc --noEmit` 通过。
- 注意：`PopoutApp.test.tsx` 在满量并行跑时偶发 3000ms 超时（Suspense 懒加载受负载影响），单独跑通过，与本次改动无关。
- 构建注意：应用运行时会锁住 `dist` 与 `public/monaco/vs`，导致 `pnpm build` EPERM；须先关闭应用再构建。
