# 工具弹出新窗口 —— 需求文档

## 1. 需求理解

用户希望 Qraft 的每个功能工具都能像 DevToys 2.0 一样「弹出为独立操作系统窗口」：主窗口保持多工具工作区不变，同时可以把任意工具（如文本比较、JSON 格式化）放到单独的窗口里并排使用，适合双屏/多任务场景。

## 2. 功能需求

### 2.1 触发入口（统一 UI 机制）

所有工具共用同一套触发机制，共三处入口：

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 标题栏按钮 | 主窗口标题栏，当前工具名/菜单栏右侧 | 图标按钮（ExternalLink），带 Tooltip 与 aria-label |
| 命令面板 | Ctrl+K 面板新增动作「在新窗口打开当前工具」 | 提供纯键盘路径 |
| 侧栏右键菜单 | 侧栏任意工具项右键 →「在新窗口打开」 | 可直达任意工具，不依赖当前选中 |

- 应用内特殊页面（设置/扩展管理）不提供弹出入口。
- 快照式一致性下允许同一工具在主窗口与弹窗同时存在。

### 2.2 窗口行为

- 每个工具**单实例**：重复触发弹出已打开的工具 → 聚焦/还原已有窗口（不重复创建）。
- 窗口尺寸按工具可配置（目录元数据 `popoutSize`），默认 900×640，最小 480×360，可缩放、居中弹出。
- 弹窗使用与主窗口一致的自定义标题栏风格（工具图标 + 名称 + 拖拽区 + 最小化/最大化/关闭）。

### 2.3 状态一致性（快照式独立窗口，已确认）

- 弹窗打开时从 localStorage 持久层载入工具状态快照（沿用现有 zustand persist 水合，零侵入）。
- 窗口之间**不实时同步**；各自编辑后各自写回持久层，最后写入者胜出。
- **关闭时回写主窗口**：弹窗关闭前 Rust 拦截（`app:popout-close-requested`），PopoutApp 冲刷该工具 store 防抖窗口内未落盘数据后再销毁；主窗口在弹窗销毁后收到 `app:popout-closed`，对对应工具执行 `hydrate(force)` 强制重读持久化状态，弹窗中的最后编辑在主窗口可见。
- 有直接子编辑器的持久化（text_compare / text_editor / json_formatter / markdown_preview）支持回写；其余工具状态无持久化则不处理。
- 不改变任何现有工具的持久化格式与水合逻辑。

### 2.4 双运行模式与错误处理

- **Tauri 桌面模式**：运行时 `WebviewWindow` 创建窗口；创建失败（权限/系统限制）→ error toast。
- **Web 模式**（浏览器 dev/预览）：`window.open` 回退；被浏览器拦截（返回 null）→ warning toast 明确告知。

### 2.5 响应式与可访问性

- 窗口逻辑像素尺寸随系统 DPI 自适应；工具组件为既有 flex 响应式布局，随窗口缩放。
- 触发按钮/菜单项均带 aria-label，Tooltip 与键盘焦点可达；弹窗内 WindowControls 复用现有带 aria-label 的控件；Esc/键盘导航遵循现有规范。

## 3. 非功能需求

- 弹窗按需加载对应工具 chunk（懒加载注册表复用），不增加主窗口首屏体积。
- 纯 Web 构建不得引入 Tauri 运行时依赖（动态 import 隔离）。
- 弹窗窗口需获得与主窗口一致的 Tauri capability 权限（工具执行/剪贴板/文件）。

## 4. 边界与风险

| 边界/风险 | 处理 |
| --- | --- |
| 多窗口并发写同一持久化 key | 快照式最后写入者胜出（产品已确认接受） |
| Monaco 等重型工具多窗口内存开销 | 独立 WebView 实例属预期行为，不做限制 |
| 文件关联/拖放打开（app:open-file） | 仅路由到主窗口编辑器，弹窗不订阅该事件 |
| 弹窗内后端工具执行 | 弹窗订阅 tool_progress/chunk/completed/failed 全局事件，与主窗口同机制 |
| 弹窗内语言/主题切换 | 弹窗订阅 config_changed 热更新 |
