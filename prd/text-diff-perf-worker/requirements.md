# 差异计算移出主线程 —— 需求文档

## 用户需求理解

文本比较 / 文件对比在大文档（约 3 万行）下，行内差异(以及并排差异)计算导致明显卡顿：
浏览器实测 30k 行、1000 处散落修改时，每次击键产生数百毫秒级主线程长任务
（单次最长 423ms，20 次编辑累计阻塞 ~54s）。根因是 `computeLineDiff`（jsdiff O(ND)）
在主线程同步执行，且每次内容变化都重算。

## 目标

- 大文档编辑/输入时，差异计算不再阻塞主线程（UI 保持可输入、可滚动）。
- 统计徽标、行级/词级高亮、概览标尺等功能与结果口径完全不变。
- 小文档行为与现状一致（同步出结果，无闪烁、无感知延迟）。

## 边界与非目标

- 行内模式切换瞬间的 ~5s 冻结主要来自 Monaco DiffEditor 自身的初次差异计算与
  行内对齐渲染（worker 内计算 + 主线程渲染），本次不处理，后续单独评估。
- 不改变差异统计语义（min 配对）与装饰注入方式。

## 验收标准

1. 30k 行 / 1000 处修改文档输入时，由我们的差异计算引起的主线程长任务（>50ms）
   消失或低于 100ms（浏览器 PerformanceObserver 复测对比）。
2. 小文档（< 30k 字符/侧）统计徽标即时更新，现有全部测试不改断言语义仍通过。
3. 大文档统计徽标最终一致（计算完成后刷新），期间显示上一次结果而非空白。
4. typecheck / eslint / vitest 全量通过。

## 验证结果（2026-08-28 浏览器实测,30k 行 / 1000 处散落修改,20 次编辑）

| 指标 | 修复前 | 修复后(并排) | 修复后(行内) |
|---|---|---|---|
| 长任务(>50ms) | ~140 次 | **0 次** | **3 次** |
| 累计阻塞 | ~54s | **0ms** | **319ms** |
| 单次最长 | 423ms | — | 213ms |

- 剩余 3 次行内长任务为 Monaco DiffEditor 自身的行内差异重算+渲染,属已知非目标。
- 验收标准 1/2/3/4 全部满足(全量测试 977/977,含新增大输入最终一致用例)。
